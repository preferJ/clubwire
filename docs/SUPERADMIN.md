# 슈퍼관리자와 운영팀 관리

서버 주소의 `/admin`에서 슈퍼관리자 PIN을 입력한다. 기본 PIN은 요청된 `7418`이며 서버의 `SUPER_ADMIN_PIN` 환경변수로 변경할 수 있다. 로그인 후에는 현재 ‘팀 관리’ 메뉴만 제공한다. `/c/{slug}/admin`은 종전과 같은 해당 팀 운영진 화면이다.

팀 목록은 실제 `CLUB` 데이터를 조회한다. 기존 DB에 YPR만 있으면 YPR만 보이며, 접속 시 임의의 팀을 생성하거나 기존 기록을 다른 팀에 배정하지 않는다. 새 팀을 생성하면 해당 팀의 관리자 PIN, 기본 설정, 기본 타이틀을 함께 초기화한다.

- 생성: 팀 이름, 고유 주소, 팀 운영진 PIN, 시간대를 지정한다.
- 수정: 팀 이름·주소·시간대와 운영진 PIN을 변경한다. 팀 ID와 소속 기록은 보존한다.
- 제거: `CLUB.ACTIVE_YN=false`로 전환한다. 선수·일정·경기·기사·통계·관리자 계정을 삭제하지 않는다. 공개 조회, 기존 팀 운영진의 조회·쓰기, 새 WebSocket 접속을 차단하고 열려 있던 해당 팀의 연결도 종료한다.
- 복원: ‘제거된 팀’ 목록에서 복원한다. 같은 팀 ID와 기존 기록, 팀 운영진 PIN을 유지한 채 다시 접근할 수 있다. 제거된 팀의 주소도 다른 팀에서 재사용할 수 없다.

슈퍼관리자 토큰은 `SUPER_ADMIN` 역할이며 브라우저의 `clubwire.superadmin`에 별도로 보관한다. 팀별 `ADMIN` 토큰과 서로 바꿔 사용할 수 없다. PIN은 프론트엔드에 포함하지 않으며 인증 실패 횟수를 별도로 제한한다.

## 기존 데이터의 소속팀 FK

사용자가 확인한 기존 FK 재사용 방식을 따른다. 중복 `CLUB_ID` 추가나 기존 데이터 재배정은 하지 않는다. 이 기능을 적용하기 위한 새 DB 마이그레이션은 없다. 단, 기존 마이그레이션은 정상 적용돼 있어야 한다.

| 데이터 | 소속팀 확인 경로 |
| --- | --- |
| 팀 관리자·선수·일정·팀 설정 및 이력 | 각 행의 `CLUB_ID → CLUB.CLUB_ID` |
| 평점·평점 이력·선수 통계·선수 조합 통계 | 각 행의 `CLUB_ID → CLUB.CLUB_ID` |
| 타이틀 종류·수상 이력·Insight·기사 | 각 행의 `CLUB_ID → CLUB.CLUB_ID` |
| 일정 참석·게스트·편성·팀·배정 이력 | 일정 FK를 거쳐 `SESSION.CLUB_ID` |
| 경기·출전 선수·경기 이벤트 | 경기 FK를 거쳐 일정 및 `SESSION.CLUB_ID` |
| Insight 선수 연결 | `INSIGHT_ID → INSIGHT.CLUB_ID` |
| 기사 사용 사실·기사 태그 | `ARTICLE_ID → AI_ARTICLE.CLUB_ID` |
| Insight 유형·유형별 규칙 파라미터 | 모든 팀이 함께 사용하는 공용 기준정보 |

팀별 REST 요청은 URL의 팀과 대상 선수·일정·기사의 소속을 확인하며, 슈퍼관리자 API는 별도의 전역 인증을 요구한다. 테스트는 다른 팀의 선수 ID 사용 거절, 팀별 집계 분리, 제거 후 접근 차단, 복원 시 같은 ID·기록 보존을 검증한다. 기존 단일 FK를 복합 FK 제약으로 일괄 변경하는 작업이나 JSON 스냅샷 내부 ID의 정규화는 이번 변경에 포함하지 않는다.

## API

아래 관리 API는 `POST /api/admin/auth`를 제외하고 슈퍼관리자 Bearer 토큰이 필요하다.

| Method | 경로 | 내용 |
| --- | --- | --- |
| POST | `/api/admin/auth` | `{ "password": "7418" }`로 로그인 |
| GET | `/api/admin/me` | 전역 관리자 인증 확인 |
| GET | `/api/admin/clubs` | 운영 중인 팀과 제거된 팀, 소속 기록 건수 |
| POST | `/api/admin/clubs` | 팀 생성 |
| PATCH | `/api/admin/clubs/{club_id}` | 팀 정보·운영진 PIN 수정 |
| DELETE | `/api/admin/clubs/{club_id}` | 기록을 보존하고 팀 접근 중지 |
| POST | `/api/admin/clubs/{club_id}/restore` | 팀 복원 |

적용 후에는 백엔드를 재시작하고 `frontend`에서 `npm run build`로 화면을 다시 빌드한다. 기존에 생성한 팀과 기록을 삭제하거나 초기화하는 명령은 필요하지 않다.
