# 팀 마크와 다크·화이트 테마

팀 관리자 메뉴의 **팀 마크 · 테마**에서 해당 팀의 마크와 기본 테마를 관리한다. 경로는 `/c/{slug}/admin/appearance`이며, 기존 팀 관리자 PIN으로 로그인한다.

## 팀 마크

- 기본 마크: 지금까지 사용한 팀 이름 기반 방패 마크. 기존 클럽은 계속 이 마크를 사용한다.
- 직접 만들기: 방패·원형·둥근 사각형, 단색·세로 줄무늬·대각선, 바탕색·테두리색·글자색, 최대 6자 문구, 축구공·별 심볼을 조합한다.
- 이미지 등록: 정적 PNG·JPG·WebP 파일을 선택한다. 선택한 파일은 밝은/어두운 화면에서 미리 보고 **변경 사항 저장**을 눌러 등록한다. 선택이나 미리보기만으로 저장하지 않는다.
- 기본 마크 복원: 저장 시 등록한 이미지까지 지운다. 마크 변경과 팀 기본 테마 변경은 함께 저장할 수 있다.

이미지는 최대 2MiB, 가로·세로 4096px 및 총 1600만 화소 이하다. 서버가 실제 이미지 형식·픽셀 데이터를 확인하고, 최대 512px의 정적 PNG로 변환하며 EXIF 등 메타데이터를 제거한다. 투명 배경은 유지한다. SVG·GIF·움직이는 이미지·외부 이미지 URL은 받지 않는다.

저장한 이미지와 디자인은 해당 `CLUB` 행에 귀속된다. 파일 경로나 별도 업로드 디렉터리가 필요하지 않으며, 공개 응답에는 이미지 데이터 대신 팀별 이미지 URL을 전달한다. 이미지 교체 시 URL 버전이 바뀌므로 이전 캐시가 남아도 새 마크를 불러올 수 있다. 다른 팀의 관리자 토큰으로 수정할 수 없고, 제거된 팀은 이미지 조회도 차단한다.

저장 후 현재 화면의 팀 마크를 갱신하며, 연결 중인 다른 방문자 화면에도 외형 변경 이벤트로 반영한다. 기존 팀 이름·선수·일정·경기·통계·기사 데이터는 바꾸지 않는다.

## 화면 테마

화면 상단의 해/달 버튼으로 다크 모드와 화이트 모드를 바꾼다. 개인 선택은 현재 브라우저에 저장되며 새로고침·다른 메뉴 이동 후에도 유지한다. 같은 브라우저의 다른 탭에도 동기화한다. 브라우저 저장소 사용이 제한된 경우 현재 창에서는 전환할 수 있다.

관리자가 저장하는 **팀 기본 테마**는 개인 테마를 선택하지 않은 방문자에게 적용된다. 이미 개인 선택이 있는 방문자의 설정은 덮어쓰지 않는다. 클럽 밖의 슈퍼관리자 화면에서도 테마 전환을 사용할 수 있다.

배경·카드·메뉴·폼·시트·토스트·기사·경기장 색상을 테마에 맞춰 변경한다. LIVE 점수판 같은 강조 패널은 읽기 쉬운 고유의 어두운 색을 유지한다. 업로드한 이미지와 마크 디자인 자체의 색상은 반전하지 않는다.

## 적용 방법

소스 갱신 후 저장소 루트에서 다음을 실행한다.

```bash
pip install -r requirements.txt
alembic upgrade head
cd frontend
npm run build
```

이후 백엔드를 재시작한다. 실행 중인 가상환경의 `pip`와 `alembic`을 사용해야 한다. 이번 변경은 Pillow 의존성과 `0011` 마이그레이션이 필요하다. `0011`은 `CLUB`에 엠블럼 설정·이미지·기본 테마·수정 시각의 nullable 컬럼만 추가한다. 기존 행은 자동 마크·다크 모드로 해석하며 데이터 초기화나 팀 재생성은 필요하지 않다.

## API

공통 접두사: `/api/clubs/{club_slug}`.

| 인증 | Method | 경로 | 용도 |
| --- | --- | --- | --- |
| 공개 | GET | `/appearance` | 마크·이미지 URL·기본 테마 조회 |
| 팀 관리자 | PATCH | `/admin/appearance` | 변경한 외형 필드를 한 번에 저장 |
| 공개 | GET | `/appearance/crest` | 현재 이미지 마크를 PNG로 조회 |

PATCH 필드는 `crest`, `imageDataUrl`, `defaultTheme`이다. 생략한 필드는 유지하며 `imageDataUrl: null`만 이미지를 삭제한다. 이미지 모드로 변경할 때는 기존 이미지 또는 같은 요청의 새 이미지가 필요하다. 기본 마크로 복원하며 이미지를 삭제하려면 `crest.mode="auto"`와 `imageDataUrl=null`을 함께 보낸다. 이미지·색상·모드 등 검증에 실패하면 같은 요청의 테마도 저장하지 않는다.
