# 경기 영상: 골 기록 주변 클립과 움직임 후보

`video` 브랜치의 관리자 실험 기능입니다. 경기 상세 아래 **골 장면 찾기**에서 영상과 영상 속 경기 시작 시점(초)을 입력합니다. 시각이 기록된 취소되지 않은 골마다 전후 30초를 추출하고, 클립의 움직임이 큰 지점을 최대 3개 추천합니다. 영상 끝/시작에서는 60초보다 짧아집니다. 영상 범위를 벗어난 골은 건너뛴 이유를 표시합니다.

## 실제로 하는 분석

FFmpeg로 클립을 만들고, 초당 2프레임·160×90 회색조 프레임의 픽셀 차이 평균을 계산합니다. 최소 5초 간격으로 높은 점수 3개를 선택합니다. 후보 버튼을 누르면 영상의 해당 시점으로 이동합니다. 가만히 있는 영상은 후보가 없을 수 있습니다.

**공 추적·골라인 판독·자동 득점 판정 모델은 아닙니다.** 선수 이동, 카메라 흔들림, 조명 변화에도 반응합니다. 실제 골 장면은 관리자가 확인합니다. 기존 점수/골 기록을 자동 수정하지 않습니다.

골 시각은 업로드 당시 기록을 스냅샷으로 보관합니다. 골 기록을 수정/취소한 뒤에는 기존 영상을 삭제하고 다시 업로드하세요. 편집하지 않은 경기 하나의 연속 영상이 기준입니다. 경기 시작 오프셋과 앱 타이머 일시정지/재개 시간을 보정하지만 촬영 중단, 편집된 영상, 잘못 입력한 기록 시각은 자동 복구하지 않습니다.

## 설치

FFmpeg와 ffprobe를 서버 PATH에 설치합니다. Windows에서는 예를 들어 `winget install --id Gyan.FFmpeg -e`로 설치한 뒤 터미널을 새로 열어 `ffmpeg -version`, `ffprobe -version`으로 확인합니다. Ubuntu는 `sudo apt install ffmpeg`를 사용할 수 있습니다.

```powershell
cd C:\clubwire
git switch video
git pull origin video
.\.venv\Scripts\python.exe -m alembic upgrade head
cd frontend
npm ci
npm run build
cd ..
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

새 migration은 `0017`, MATCH_VIDEO.MATCH_ID FK로 경기·일정·클럽에 연결합니다. 모든 영상 API는 해당 클럽 관리자에게만 허용합니다. 영상 파일은 공개 static 경로에 노출하지 않습니다.

환경 설정:

```ini
VIDEO_STORAGE_DIR=./uploads/match-videos
VIDEO_MAX_MB=1024
```

기본 최대 1GB, 영상 4시간/4K 이하. 지원 입력은 MP4/MOV, MKV/WebM, AVI, MPEG-TS이며 코덱 지원은 서버 FFmpeg에 따릅니다. 파일 확장자만 믿지 않고 실제 스트림을 검사합니다. 영상 전송은 HTTP raw body를 사용하므로 별도 multipart 패키지가 필요 없습니다. 프록시/터널의 업로드 크기·시간 제한도 확인하세요. 대용량 업로드의 재개 기능은 없습니다.

## 운영 및 저장

- 이 버전은 **uvicorn worker 1개**를 사용합니다. 프로세스 내 영상 분석도 한 번에 하나만 실행하고 FFmpeg 스레드를 제한합니다. 대규모 운영은 별도 작업 큐/영상 worker로 분리해야 합니다.
- 분석 후 원본은 삭제하고 클립·결과만 남깁니다. 재분석하려면 원본을 다시 업로드해야 합니다. 사용자 기기의 원본은 삭제하지 않습니다.
- 작업 중 서버가 재시작되면 다음 시작 때 중단 상태를 실패로 표시하고 임시 파일을 정리합니다. 자동 재시도하지 않습니다.
- 클립은 관리자 삭제 전까지 보관합니다. 골이 많으면 겹치는 구간도 각각 저장하므로 저장 공간을 관리하세요. 업로드 시 여유 공간 512MB를 확보하며, 분석 중 공간 부족은 실패로 표시합니다.
- DB만 백업하면 실제 클립은 복원되지 않습니다. VIDEO_STORAGE_DIR도 함께 백업하세요. 테스트 데이터 초기화 도구는 DB 행만 삭제하므로 별도로 영상 저장 공간을 정리해야 합니다.
- 2GB 서버에서도 저해상도 움직임 분석을 사용하지만 원본 디코딩·인코딩은 CPU/메모리를 사용합니다. 긴 영상은 기다려야 하며 실제 서버에서 처리 시간을 확인하세요.
